# 04 · CI with GitHub Actions

|                     |                                                                                   |
| ------------------- | --------------------------------------------------------------------------------- |
| **Goal**            | Turn lint, types, unit tests, build and e2e into required checks that gate `main` |
| **Time box**        | 10 minutes (42–52)                                                                |
| **Starting branch** | `step-3-e2e` (solution: `step-4-ci`)                                              |

```bash
git checkout step-3-e2e
```

## Steps

1. **Draft the workflow with Copilot** ([prompt 4.1](prompts.md#41-workflow)). Ask for `.github/workflows/ci.yml`, then compare the result with the requirements below. Copilot often pins a pnpm version or forgets `--frozen-lockfile`.

2. **Understand the gates.** The workflow is named `CI` and runs on `pull_request`, on `push` to `main`, and on `workflow_dispatch`.

   | Job / step                                       | Gate                                                                                                                                                               |
   | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
   | `concurrency: ci-${{ github.ref }}`              | A new push cancels the stale run for the same ref                                                                                                                  |
   | `permissions: contents: read`                    | Least privilege for `GITHUB_TOKEN`                                                                                                                                 |
   | `pnpm/action-setup@v4`                           | No `version:`. It reads `packageManager` (`pnpm@12.15.0`) from `package.json`                                                                                      |
   | `actions/setup-node@v4` (Node 24, `cache: pnpm`) | Same Node as local, and cached installs                                                                                                                            |
   | `pnpm install --frozen-lockfile`                 | Fails if `pnpm-lock.yaml` is out of sync with `package.json`                                                                                                       |
   | **quality**: `pnpm lint`                         | ESLint with angular-eslint                                                                                                                                         |
   | **quality**: `pnpm typecheck`                    | `tsc --noEmit` for the app, spec and e2e tsconfigs                                                                                                                 |
   | **quality**: `pnpm test:coverage`                | Vitest. The `coverage/` artifact is uploaded with `if: always()`                                                                                                   |
   | **quality**: `pnpm build`                        | The SSR Worker bundle compiles                                                                                                                                     |
   | **e2e** (`needs: quality`)                       | `playwright install --with-deps chromium`, then `pnpm e2e` with `CI: true` (no server reuse, 2 retries, `forbidOnly`). `playwright-report/` is uploaded on failure |

   There's no deploy job. Cloudflare Workers Builds deploys from Git (module 05), so CI never needs Cloudflare credentials.

3. **Lint the workflow** (optional, needs Go):

   ```bash
   go run github.com/rhysd/actionlint/cmd/actionlint@latest
   ```

   CodeRabbit also runs actionlint on PRs, because it's enabled in `.coderabbit.yaml`.

4. **Push and open a PR.** Commit on a branch, push it, and open a PR in your fork (base `step-3-e2e`):

   ```bash
   git checkout -b ci/workflow
   git add .github/workflows/ci.yml
   git commit -m "ci: lint, typecheck, test, build, e2e"
   git push -u origin ci/workflow
   ```

   Open the **Actions** tab. `quality` runs first, then `e2e`. On a fork, you may need to click **I understand my workflows, go ahead and enable them** on the Actions tab first. On the PR, the checks list shows `CI / quality`, `CI / e2e` and CodeRabbit.

5. **Protect `main`.** Go to **Settings → Rules → Rulesets → New ruleset → New branch ruleset**:
   - Enforcement status: **Active**. Target branches: **Include default branch**.
   - Tick **Require a pull request before merging**.
   - Tick **Require status checks to pass**, then **Add checks** → `quality` and `e2e`. A check only shows up in the picker after it has run once in the repo. Optionally add the **CodeRabbit** check too.
   - Tick **Block force pushes** and save.

   Classic **Settings → Branches → Add branch protection rule** works too.

6. **See a gate fail.** Push a commit that breaks something, for example by cherry-picking the bulk-discount commit from module 01 (`git cherry-pick <sha>`). `e2e` goes red because SSR returns 500, and the PR can't be merged.

## Expected result

- A green `CI` run with the `quality` and `e2e` jobs, plus the downloadable `coverage` artifact.
- `main` can only change through a PR with both checks green.

## If stuck

- **Workflow doesn't run.** Enable Actions on the fork (Actions tab), and check that the file is at `.github/workflows/ci.yml`.
- **`ERR_PNPM_OUTDATED_LOCKFILE`.** Run `pnpm install` locally and commit `pnpm-lock.yaml`.
- **e2e: browser missing.** Make sure the `playwright install --with-deps chromium` step runs before `pnpm e2e`.
- **Take the solution:**

  ```bash
  git checkout origin/step-4-ci -- .github
  ```
